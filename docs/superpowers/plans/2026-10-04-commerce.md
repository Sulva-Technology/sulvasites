# Commerce Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real shops on Sulva Sites — catalogue, cart, Paystack checkout (platform subaccounts or shop's own keys), orders, a first-class shop admin, and two e-commerce templates (t13 Mode, t14 Cartly).

**Architecture:** Postgres tables + RLS (reusing `site_members` helpers) hold catalogue/orders; payment secrets live in a service-role-only table (own keys AES-GCM encrypted). Pure TS libs (money, cart, pricing, signature, secretBox) are unit-tested; Next API routes do authoritative pricing, Paystack init/verify/webhooks and settings. Shared storefront plumbing (loader, `useCart`, shop routes under `/shop/...`) feeds new optional template props consumed by t13/t14. Shop admin is a set of shared components mounted under `/admin/sites/[siteId]/shop` (dashboard later).

**Tech Stack:** Next.js 16, React 19, Supabase (Postgres/RLS/service role), Paystack REST API, Node `crypto` (HMAC-SHA512, AES-256-GCM), Node test runner, Tailwind (admin), scoped CSS (templates).

**Spec:** `docs/superpowers/specs/2026-10-04-commerce-design.md`

## Global Constraints

- Money is integer **kobo** everywhere; display via `formatNaira`. Currency 'NGN'.
- Never trust client prices: server re-prices from DB on checkout.
- Secrets: `PAYSTACK_SECRET_KEY`, `SHOP_SECRETS_KEY` (base64 32 bytes) server-only; per-shop secret keys only ever stored encrypted in `shop_payment_secrets` (no client RLS policies); API responses show masked last4 only; never log secrets.
- Paystack base URL `https://api.paystack.co`; `Authorization: Bearer <secret>`; amounts in kobo.
- Shop routes live under `/shop/...`: `/shop`, `/shop/c/[category]`, `/shop/cart`, `/shop/checkout`, `/shop/order/[reference]`, `/shop/[product]` (deviation from spec's `/cart` etc. to avoid clashing with the `[pageKey]` route — record in spec).
- Migration 006 depends on 005 (`is_site_member`, `can_edit_site`).
- Modules loaded by `npm test` use relative `.ts` imports.
- Existing source files are CRLF → Edit tool. Another session has uncommitted work in this checkout: never touch it; commit with `git commit --only -- <paths>`. Commit messages end with blank line + `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Templates t13/t14 follow every t7–t12 convention (see `docs/superpowers/specs/2026-10-03-category-templates-design.md` Shared conventions + the review rules recorded in `.superpowers/sdd/2026-10-03-category-templates/progress.md` carry-forward lines).

### Task 2: Pure shop libs (TDD)

**Files:** Create `src/lib/shop/money.ts`, `cart.ts`, `pricing.ts`, `paystackSignature.ts`, `secretBox.ts`; tests `tests/shopMoney.test.mjs`, `tests/shopCart.test.mjs`, `tests/shopPricing.test.mjs`, `tests/shopCrypto.test.mjs`.

**Interfaces — Produces:**
```ts
// money.ts
export function formatNaira(kobo: number): string;            // 150000 -> "₦1,500" ; 150050 -> "₦1,500.50"
export function toKobo(naira: number): number;                // Math.round(naira*100)
export function platformFeeKobo(totalKobo: number, bps: number): number; // floor(total*bps/10000)
// cart.ts
export type CartLine = { productId: string; variantId: string | null; quantity: number };
export function addLine(lines: CartLine[], line: CartLine, max?: number): CartLine[]; // merges same product+variant, caps qty at max (default 99)
export function setQty(lines: CartLine[], index: number, qty: number): CartLine[];    // qty<=0 removes
export function removeLine(lines: CartLine[], index: number): CartLine[];
export function cartCount(lines: CartLine[]): number;
export function parseCart(raw: string | null): CartLine[];   // tolerant JSON parse, drops invalid lines
export const cartStorageKey: (siteId: string) => string;     // `sulva-cart-${siteId}`
// pricing.ts
export type PricedProduct = { id: string; name: string; price_kobo: number; active: boolean };
export type PricedVariant = { id: string; product_id: string; price_kobo: number | null; stock: number | null; options: Record<string, string> };
export type ShopPricingSettings = { delivery_fee_kobo: number; pickup_enabled: boolean };
export type PriceProblem = { lineIndex: number; reason: "unavailable" | "out_of_stock" | "insufficient_stock" | "variant_required"; available?: number };
export function variantLabel(options: Record<string, string>): string; // {"Size":"M","Colour":"Black"} -> "M / Black"
export function priceCart(lines: CartLine[], products: PricedProduct[], variants: PricedVariant[], settings: ShopPricingSettings, deliveryMethod: "delivery" | "pickup"):
  { items: Array<{ lineIndex: number; productId: string; variantId: string | null; name: string; variantLabel: string | null; unitKobo: number; quantity: number; lineTotalKobo: number }>; subtotalKobo: number; deliveryKobo: number; totalKobo: number; problems: PriceProblem[] };
// paystackSignature.ts
export function verifyPaystackSignature(rawBody: string, signature: string | null, secret: string): boolean;
// secretBox.ts
export function encryptSecret(plain: string, keyB64: string): string;  // "v1:<iv b64>:<tag b64>:<data b64>"
export function decryptSecret(box: string, keyB64: string): string;     // throws on tamper/wrong key
```
Rules: pricing — product missing/inactive → `unavailable`; product has variants but line.variantId null → `variant_required`; variant stock 0 → `out_of_stock`; qty > stock → `insufficient_stock` with `available`; unit = variant.price_kobo ?? product.price_kobo; problem lines excluded from totals; delivery fee only for `delivery` and only when subtotal > 0; `deliveryKobo = method === "delivery" && subtotal > 0 ? delivery_fee_kobo : 0` (rejecting pickup when `pickup_enabled` is false is the checkout route's job, not priceCart's).

- [ ] Write tests first covering every rule above (incl. formatNaira rounding/thousands, addLine merge + cap, parseCart garbage, signature valid/invalid/null/length-mismatch, secretBox round trip + tamper + wrong key). Run → FAIL. Implement (node `crypto`: `createHmac('sha512')`, `timingSafeEqual`, `createCipheriv('aes-256-gcm')` 12-byte IV). Run → PASS. Commit "Add pure shop libraries".
